# [IMC '26] Beyond QCI: Understanding Performance Competition Between an MVNO and Its Host MNO

In this repository, we release the dataset and scripts used in the IMC '26 paper,
*Beyond QCI: Understanding Performance Competition Between an MVNO and Its Host MNO*.

## Operator anonymisation

The paper anonymises the three U.S. host MNOs as **HA**, **HB** and **HC**, and their
two MVNOs as **VA1/VA2**, **VB1/VB2** and **VC1/VC2**. This repository uses the same
labels throughout — in directory names, file names and CSV column headers — so that
nothing here identifies the commercial operators. `family_a`, `family_b` and
`family_c` correspond to Families A, B and C in the paper.

## Repository Structure & Usage

- **`raw_data/`**
  The original measurement data, one subtree per operator family.

  - `raw_data/family_*/iperf/<city>/<operator>/location_*/round_*/<scenario>/<role>/<timestamp>_<direction>_s<N>/*.out`
    Raw `iperf3` console output, one file per run. The five contention scenarios
    appear as the folder names `M`, `V1`, `V2`, `M+V1`, `M+V2`, `V1+V2`, `M+V1+V2`
    (host = `M`, MVNO 1 = `V1`, MVNO 2 = `V2`), and `<role>` is `main`, `virtual_1`
    or `virtual_2`. Each `.out` file carries a short header naming the location,
    round, scenario and direction.
    For Family C, `boston` holds the main campaign and `boston_uplink` a
    supplementary uplink-only campaign.

  - `raw_data/family_*/xcal/*.csv.gz`
    XCAL radio-side logs, gzip-compressed (`pandas.read_csv` opens them
    directly; the plain-`csv` readers in the scripts use `gzip.open`). `*_RBs.csv.gz` carry per-sample PCI, NR-ARFCN, bandwidth,
    DL/UL resource-block counts and MAC throughput; `*_MAC_TP.csv.gz` /
    `*_MAC_Throughput.csv.gz` carry NR and LTE MAC-layer throughput; `*_case.csv.gz` are
    the wide multi-carrier exports behind the per-run breakdown tables in the paper.
    City suffixes are `BOS` (Boston), `ATL` (Atlanta) and `PHI` (Philadelphia).

  - `raw_data/family_*/valid_data_range.txt`
    The rounds retained after the plan-cap filtering described in §3 of the paper,
    broken down by scenario, city, location and by *all valid* / *5G only* /
    QoS-class subsets. Every analysis script reads its round list from here.

  - `raw_data/locations.txt` — coordinates of the measurement sites.

- **`scripts/`**
  Two kinds of script, all reading from `raw_data/` and writing to `plots/`:

  1. **Figure scripts** — `generate_figures.py` produces the per-family and
     cross-family throughput box plots and writes the win-count tables to
     `statistic.md`; `generate_city_boxplots.py` and `generate_city_merged.py`
     produce the city-level comparisons; `generate_pci_boxplots.py` and
     `generate_familyC_pci_qci_boxplots.py` condition on serving-cell (PCI) and
     QoS-class context; `generate_familyC_mac_charts.py` produces the stacked
     NR/LTE MAC-layer charts; `familyA_matched_rb_mac.py` and
     `familyBC_matched_rb_mac.py` produce the matched-radio-context RB and MAC
     figures; `mac_ul_stacked_bar_loc2.py` and `ul_iperf_barplot_atlanta_loc1.py`
     produce the two single-location Family A figures.
  2. **Consistency / bookkeeping scripts** — `campaign_timeline.py`,
     `familyB_diff_winners.py`, `familyC_5gonly_vs_allvalid.py` and
     `familyC_qci_winrate.py` cross-check `valid_data_range.txt` and report the
     round counts and win rates quoted in the text. `plot_locations.py` renders an
     interactive map of the sites and is the only script needing `folium`.

  Run them from inside `scripts/`, for example:
  ```bash
  cd scripts && python3 generate_figures.py
  ```

- **`plots/`**
  The generated figures. All 46 figures in the paper are reproduced here
  bit-for-bit by the scripts above, except `Bos_loc.png`, `Atl_loc.png`,
  `Phi_loc.png` and `mno_architecture.png`, which are hand-drawn. The directory
  also holds additional variants the scripts emit that the paper does not use
  (half-width city plots, QoS-class-999 splits, and so on).

- **`statistic.md`** — win-count tables regenerated by `generate_figures.py`.
